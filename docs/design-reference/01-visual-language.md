# 01 · 视觉语言（Visual Language）

> 标记含义见 `README.md`：**[官方源码]** / **[官方素材]** / **[官方文案]** / **[社区分析]** / **[推断]**

## 1. 风格定位

终末地的平面设计不是"科幻光效"，而是**工业标识系统 + 工程制图 + 战术 HUD** 的合成。它最容易被误读为"暗色科技风"，实际差异在于：**信息密度高、色彩克制、无彩色渐变、发光仅用于极少数强调态**。

> **两条边界先立在这里**（515 帧实机复核 + 400KB 官方 CSS 复算后的修正）：
>
> - **"渐变"要分彩色与明度**。官方 CSS 的 101 处 `linear-gradient` **没有一处是"彩色→彩色"的插值**：它们全是 ①黑/白透明遮罩的淡出端（`linear-gradient(180deg,rgb(0,0,0) 0,rgb(0,0,0) 60%,rgba(0,0,0,0) 90%)` ×10）、②**硬停色标**（`linear-gradient(90deg,#ff00f0 11.25rem,#fffa00 0,#fffa00 22.5625rem,#00ffa2 0)` —— CMYK 色条，三段之间零插值）、③45° 斜线 hatching。但实机帧里**大面积的单色明度渐变是常态**（展示页的聚光+暗角、浮层的半透明黑纱）。⇒ 禁彩色渐变，**留明度渐变**。**[官方源码]** + **[实机帧]**
> - **"发光"不是零**。官网 26 条阴影声明里有 **8 条是真实光晕**，且**色相只有白与 `#fff000`**：`text-shadow:0 0 .25rem #fff,0 0 .5rem #fff,0 0 .75rem #fff` ×3、`box-shadow:0 0 10px #fff000` ×2、`box-shadow:0 0 1rem hsla(0,0%,100%,.8)` ×2、`text-shadow:0 0 1rem hsla(0,0%,100%,.5),…` ×1。实机同样只有两类光：**选中描边的柔光晕**与**展示页背景的柔光雾**。⇒ 禁彩色辉光/霓虹 bloom，**留白/黄单色柔光**。**[官方源码]** + **[实机帧]** `frames2/uilook-108.jpg`

| 描述词 | 定义 | 视觉体现 |
|--------|------|---------|
| **工业风 Industrial** | 工业控制面板 / 生产线监造台 | 深灰黑底 + 警示黄高亮；面板有仪表面板的"拟物质感" |
| **机能风 Techwear** | 功能决定形态 | 军规搭扣、插扣、拉链语汇；无冗余装饰 |
| **磁带盒未来主义 Cassette Futurism** | 80–90 年代科幻 | 长条形黑色主视觉块、半透明塑料质感、大按键 |
| **画内界面 Diegetic Interface** | 角色也能"看到"的界面 | 全息投影、虚拟视窗、HUD 悬浮框 |
| **HUD / 战术抬头显示** | 专业、克制 | 等高线、坐标、准星、扫描线 |
| **高级灰 + 局部高对比** | 大面积低饱和冷灰打底，局部一个高对比强调色 | 「灰调打底、提高局部对比度」 |
| **工程制图 / 蓝图** | 图纸、测绘、专利插图 | 框线 + 对角线、剖面线、尺寸标注、等高线底纹 |

**配色母本**：社区分析直接类比 **卡特彼勒 CAT 工程机械的黄黑白配色**（"卡特黄"专利史）—— 黄色 = 警示、视觉引导、防止视觉疲劳。[社区分析]

**一句话气质**：*把整个界面做成一台还在运转的工业设备的技术面板。*

### 2.5 语义色（⚠ 无官方 token）

官方 CSS 里**没有**独立的 warning / success / error token —— **警示本身由信号黄承担**（"黄色即警示"是这套语言的核心逻辑）。皮肤需要独立语义色时：

| 语义 | 建议值 | 依据 |
|------|--------|------|
| success | `#00FFA2` | 官方已有色，量最少改动 |
| warning / 进行中 | `#FFFA00` | 官方主强调 |
| error / 危险 | `#EC1313` / `#F25A5A` | **[定案]** shell 自身错误红（`--dsw-static-red-600` / `-400`）；下面的实机补充推翻了早期"用 `#FF1AAC`"的推断 |

**实机补充（红色是"状态"不是"强调"）**：实机确实存在一个独立的**不足/不可用红**——`frames2/uilook-092.jpg` 的确认弹窗里，数量充足的数值是深色字，而**低于需求的数值被标成红色**（该弹窗需求 `赤晶玉×4000`，库存 `1 / 1 / 50`，第三个 `50` 为红）。它只用于数值与资源不足提示，**不进入装饰体系、不做按钮底色**（同屏的主 CTA 仍是黄底）。⇒ 上表 `error / 危险 = #FF1AAC` 的推断应下调优先级：皮肤做**数据校验/失败**语义时用实机这套**暖红**更贴；品红继续只做"稀有/警示徽记"。**[实机帧]**（红色具体值受压缩影响，未取得可靠单值，故不给 token）

> **已落地（皮肤当前行为）**：`--dsw-alias-state-error-primary / -secondary` 与 `--dsw-alias-interactive-bg-hover-danger` 现在都走上面的红 —— 正文里 tool / turn 的 "Error" 文字因此是红的，而不再被品红接管。实机红的具体 hex 取不到（有损压缩），所以直接沿用 shell 自己那一档（`#EC1313` / `#F25A5A`，见 `src/client/palette.ts` 的 `ERROR_RED`）：既满足"失败必须是红"，又不引入一个没有出处的红色。

**浅色模式的五条排版规则（实机）**：

1. **主类型是深色字**；画布接近白，分区全靠 **1px 结构与留白**，不用色块底。属性行 = 图标 + 名称 + 右对齐数值，行间发丝线。**[实机帧]** `frames2/menunav-049.jpg`
2. **白字只出现在两处**：① 展示页**大标题**（白字 + 极细深描边，故意低对比，**[实机帧]** `frames2/charanim-003.jpg` 的 `Chen Qianyu`）；② **画在黄色器件之上**的字（`charanim-003.jpg` / `charanim-014.jpg` 的竖排 `ENDFIELD`、`frames2/charanim-003.jpg` 的 `LEVEL/80`）。
3. **黄色器件是浅色模式的骨架，不是点缀**。已确认五种形态：**大扇形楔块**（圆心在屏幕外、弧形边缘扫过整屏，**[实机帧]** `frames2/charanim-030.jpg`）、**窄竖带**（贯穿内容区一条，**[实机帧]** `frames2/menunav-031.jpg`、`frames2/charanim-014.jpg`）、**45° 斜切条**（**[实机帧]** `frames2/charanim-003.jpg` 右上）、**选中描边**（**[实机帧]** `frames2/uilook-108.jpg` 的六边形、`frames2/uilook-159.jpg` 的黄色高亮框）、**标题下的短横杠**（**[实机帧]** `frames2/menunav-057.jpg` 的 `// OUTPOST INFO`、`frames2/menunav-056.jpg` 的属性栏标题）。
4. **左侧栏 + 右侧属性栏的两段式**是浅色页的默认骨架；顶栏是**方形面包屑芯片 + 方形搜索框**（**[实机帧]** `frames2/menunav-049.jpg`），底部是一条深色命令带。
5. **巨大浅色数字水印**在实机也在用：数据库首页的 `01`–`06` 目录项用巨大浅灰数字 + 线稿图标铺底（**[实机帧]** `frames2/menunav-047.jpg`），威胁档案页底部压着极淡的徽记 + `终末地` 字标（**[实机帧]** `frames2/menunav-048.jpg`）。这正好印证 §4 的 `HallowText` 手法——**在浅色画布上比在深色上更好用**。

**皮肤应当从这里取的（可执行结论）**：

- DSH 的**主工作区**（会话列表、消息流、工具卡）整体切到 **`#E1DFE0` 浅灰画布 + 深色字 + 发丝线分区 + 方形面包屑芯片**；右侧固定一条**黄色竖带**作为唯一强调器件；会话/工具标题下的分隔用**标题 + 黄色短横杠 + 发丝线**，而不是色块。
- 深色 `#191919` 退回三处：**命令条（用实测 `#333532`）**、**终端/日志/代码面板**、**叠在消息流之上的浮层（半透明黑纱）**。
- 展示型卡片（工具调用的结果预览）可以用**单色明度渐变底 + 暗角**制造"聚光"，但**必须是同色明度**，不得引入第二种色相。
- 反例警告：浅色模式**必须与黄色器件同时出现**，否则退化成"普通浅色后台"。黄色是浅色模式下唯一的秩序来源。

> **可信度前提**：本文所有 [实机帧] 证据取自**测试版**画面，帧角带官方声明 `The Beta Test build is not representative of the final product`（**[实机帧]** `frames2/menunav-049.jpg`、`frames2/charanim-003.jpg` 右下角）。正式版可能调整；引用时保留此前提。

### 3.3 排版规则（**[官方源码]** 实测）

| 规则 | 取值 | 说明 |
|------|------|------|
| **全大写** | `text-transform: uppercase` ×12 | 拉丁标签一律全大写 |
| **大标题负字距** | `-.02em` ~ `-.1em`、`-1px`、`-.58rem` | 反直觉但很"终末地"：标题**压紧**，不是加宽 |
| **小标签正字距** | `.05em`（竖排小标签）→ 建议 overline 用 `.12em` | 与标题相反 |
| 字号阶梯 | `1rem` 基准 → `1.125 / 1.25 / 1.5 / 1.875 / 2 / 2.25 / 2.5 / 3rem` | 高频：1.5rem(27) > 1.25rem(22) > 1.875rem(17) |
| 超大标题 | 最高 `8.125rem` | 官网 hero |
| 字重声明 | 多为 `font-weight:400` | 因为用的是**独立字重文件**而非数值字重 |
| 文字辉光 | `text-shadow:0 0 .25rem #fff,0 0 .5rem #fff,0 0 .75rem #fff` ×3；`text-shadow:0 0 1rem hsla(0,0%,100%,.5),…` ×1 | **以白色辉光为主**，层层加宽做"点亮"感。⚠ 旧稿写的 `text-shadow: 0 0 10px #fff000` 有误：该值在 CSS 里是 **`box-shadow`**（×2，给方框用），全站 `text-shadow` 共 6 条、`box-shadow` 共 20 条，其中**带真实光晕的共 8 条，色相只有白与 `#fff000`** |
| 数字 | 建议 tabular mono / 宽体 | 配合坐标与计数器语汇 |

### 3.4 网页缩放模型（**[官方源码]**）

```js
html.style.fontSize = 16 * Math.min(vw / designW, vh / designH)   // designW/H = 2560×1440 (横屏) / 1080×1920 (竖屏)
```

整个版式按**单一比例整体缩放**，没有断点跳变（海报式布局）。⇒ 皮肤若沿用此手法，需注意 DSH 是流式应用，建议**只对装饰性元素**使用视口比例，正文保持可访问性字号。

| 旧写法 | 复核 | 精确边界 |
|--------|------|---------|
| 大面积发光 | **改口径**（不是"无发光"） | 官网 26 条阴影里 **8 条是真实光晕，色相只有白与 `#fff000`**；实机只有"选中描边柔光晕"+"展示页背景柔光雾"。⇒ 禁的是**彩色辉光、霓虹外发光、大面积 bloom、发光描边文字**；**白/黄单色柔光可以留** |
| 彩色渐变 | **成立** | 101 处 `linear-gradient` **零彩色→彩色插值**（唯一带彩的 CMYK 条是硬停）。⇒ 禁"两种色相之间的平滑过渡"；**同色明度渐变（遮罩淡出、聚光/暗角、压印）是官方主力手法，必须保留**（§2.6） |
| 圆角卡片 | **成立，但要补例外** | 大圆角卡片确实没有；但**主 CTA 全胶囊、列表行 6–10px 小圆角、头像正圆**是实机常态。⇒ 禁的是"卡片感的大圆角容器"，不是圆角本身 |
| 玻璃拟态 | **收窄为"亮色玻璃"** | 官网确有 `-webkit-backdrop-filter:blur(.3125rem)` / `backdrop-filter:blur(.3125rem)` ×2 与 `filter:blur(8px)` ×1（400KB CSS 里仅此 3 处）；实机的全屏浮层就是**半透明黑纱**（`frames2/menunav-061.jpg`）。⇒ 禁的是**亮底/彩色毛玻璃、玻璃高光边、外描边高光、厚重半透明白卡**；**低透明度的暗色纱罩是官方在用的一层，应当保留** |

**实机确认（[实机帧]）**：这套标签法**在游戏内一模一样**，可以放心直接搬进皮肤 ——

- `//` 区块前缀：`// 勲章 / 編集`（`frames2/uilook-107.jpg`）、`// MISSION`（`frames2/menunav-061.jpg`）、`// OUTPOST INFO`（`frames2/menunav-057.jpg`）、`// 四号谷地 /中核エリア`（`frames2/uilook-112.jpg`）。
- 面包屑：日文版用 `//A /B/C`，英文版用 `A > B > C`（`frames2/menunav-049.jpg` 的 `Endfield Database > Gear Files > Basic Armor`）—— **实机是 `>` 而不是官网的 ` - `**，皮肤可直接用 `>`。
- 计数器：`130/130`、`3/80`、`0/43`、`0/107`（`frames2/uilook-112.jpg`）、`0/100`（`frames2/uilook-117.jpg`），零填充与斜杠格式一致。
- **工程读数条**：实机每屏左下角常驻 `0ms  UID: 4663329443` 一类**性能/身份读数**，右下角是键位提示串 —— 这是极廉价、极"终末地"的一行装饰，皮肤可用 `12ms · <会话 id 前 10 位>` 之类复刻。**[实机帧]** `frames2/uilook-025.jpg`、`frames2/charanim-003.jpg`
